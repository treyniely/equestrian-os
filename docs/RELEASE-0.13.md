# Release 0.13 — Shared suitability and filled square logos

Horse and trainer add/edit now use one reusable level checklist, including academy custom labels and an explicit All rider levels choice. Profile cards and the customer directory show multiple suitability badges. Rider current level stays single-valued. Shared allowsRiderLevel checks drive scheduling suggestions, program-level session validation, direct bookings, admin enrollment and family booking/rescheduling eligibility. Old single-level horse records keep the earlier compatibility rule until saved with the new checklist; their prior label is preselected in the editor. Explicit new checklists match exact labels. Selecting All rider levels is stored as an empty array. New horse forms default to Beginner. No existing booking is removed or rescheduled. Dead generic horse/rider dropdowns were removed.

Opaque logos with a consistently colored perimeter now fill the entire square: the formatter detects the background and extends its edge pixels into the surrounding space. Artwork remains centered with unchanged proportions. This handles the burgundy/gold example without redrawing its text or symbol. Transparent inputs stay transparent. Highly varied/photographic perimeters are not automatically extended. Extend matching background can be turned off. Existing processing/success sparkle, 1080px output checks and downloadable PNG remain. This is automatic image processing; no AI image API is configured or invoked and generative reconstruction is not claimed.

Architecture: shared domain suitability rule and field component; bounded perimeter analysis in logo-fit and existing canvas pipeline. No new dependencies, schema migration or configuration. Tenant/role enforcement and storage paths are unchanged. Rollback by redeploying the preceding version; multi-level arrays remain in resource JSON. For rollback, older code cannot fully enforce new horse arrays, so prefer a forward fix if new suitability assignments have been saved.

Validation: full check:release (TypeScript, 88 tests, production build), whitespace diff check. New cases cover multi-level/custom/all matching, legacy compatibility, saved arrays/dedup/invalid inputs, normal edits retaining choices, admin/family horse suitability and program-level session guards, plus burgundy background detection and transparent/varied perimeter handling. Source review includes multiple badges, checkbox states/required selection, 44px targets and mobile columns, background processing status, override and square output validation. Browser visual/interaction QA remains unverified: managed preview last returned ERR_CONNECTION_REFUSED without infrastructure recovery evidence. 390/768/1440px appearance, keyboard form operation and actual logo seam/texture quality require the next working browser session. Marketing was unchanged.


## Rider photos added to this release

Parents can add, replace or remove an optional rider photo in My riders → Edit profile & favorites. The shared square photo control handles JPEG/PNG/WebP up to 8 MB and 40 MP, crops centrally and prepares WebP before uploading. Staff can manage the same photo in Riders; it appears on staff rider cards, linked riders inside the family account and the family rider card. Missing photos keep initials/name fallbacks.

POST /api/portal/photo requires authenticated family membership, same-origin requests and bounded 2 MB prepared content, validates its signature and stores a family ownership marker. Portal rider saves accept newly uploaded photo IDs only when R2 metadata matches the authenticated family; IDs and rider ownership are validated server-side. Existing unchanged staff-assigned photos remain usable. GET checks the rider’s linked family and tenant; authorized staff image access requires rider viewing permission. Rider responses/images are private with no-store. Rider photos never enter the public trainer/horse directory. Removing a photo unlinks it from subsequent authenticated reads; it does not promise deletion of previously downloaded copies. Unreferenced R2 file cleanup/retention is future operational work.

New tests cover own-family round-trip, staff visibility, no directory exposure, other-family attachment/read rejection, tenant scoping, retaining/removing the photo, upload signature/size and family ownership metadata. Browser image selection/cropping/upload/download/replace/remove and appearance remain unverified under the preview limitation above.
