# Release 0.15 — Monthly trainer planner

Calendar now offers Plan a trainer’s month. Choose a trainer/month, then add repeatable blocks with academy-named offerings, weekdays, occurrence weeks, local start time, 1–8 back-to-back sessions, optional breaks, location, horses, additional trainers and supporting interns. Preview lists individual occurrences with teaching days, totals by offering and conflicts. Uncheck individual sessions, or skip flagged sessions, before one final schedule action. Sessions are visible in the existing family booking calendar; no rider enrollments, payments or messages are generated.

Offerings use the academy’s own names. The built-in horsemanship template description no longer uses Guide N Gallop’s Horse Sense name. Private/group/class formats continue to share the existing session model.

Times use the academy IANA time zone. UTC storage remains unchanged. Weekly local times persist across daylight-saving changes. The existing Calendar day filter, display and single-session inputs now also use academy local time. Legacy-booking history still explicitly displays UTC.

Validation checks academy closures, personal availability/dates off, existing reservations/legacy bookings, overlaps within the proposed plan, horse counts/suitability, trainer suitability, intern availability and recorded absences. Review flags past starts and nonexistent local clock-change times. An excluded overlap no longer blocks a remaining occurrence. Every assigned trainer must be suitable at enrollment. No partial publication: the selected set and all resource reservations commit atomically, protected by existing database conflict triggers. Repeat saves use a fingerprinted tenant-scoped batch ledger to avoid duplicates and reject changed payloads sharing a save key.

Architecture: shared pure plan expansion/selection, a focused schedule service, and one planner component. No new dependencies. Planner queries only scheduling resources and the selected month’s work/attendance; it does not load the CRM, financial records or historical drafts. Resource-work calculations are cached. One plan supports 100 sessions / 800 writes, with clear errors rather than silent partial saves. Plans create individual session occurrences; there is no ongoing recurring-series editor or automatic future-month copying. Interns reserve the full session; this does not automatically create a separate intern task, and existing Barn team task planning remains available. Manually assigned interns still follow existing attendance/task-management behavior.

Migration: 0012_heavy_kree adds schedule_batches with a unique tenant/request key index. No configuration or secrets. Rollback: restore 0.14; leave the additive ledger table in place. Audience remains owner-private. Schedule preview/publication require schedule management permission and same-origin authenticated API requests.

QA: TypeScript, 105 automated tests and production build passed before publication. Added coverage for local DST recurrence, selected weeks/dates, closure/time-off/absence flags, conflict removal, both trainers and interns reserved, family booking visibility, tenant and permission boundaries, retry safety, atomic rollback on a concurrent booking, mounted horse requirements, all-trainer suitability and back-to-back totals/breaks. Shared UI controls reviewed in source for spacing, checkbox hit areas, responsive wrapping, fixed dialog close and ghost CTAs.
