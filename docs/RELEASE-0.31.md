# Release 0.31 — Setup that finishes, and an operational overview

The academy checklist now verifies business name/contact, explicitly saved operating hours/time zone, trainer schedules, active offerings, conditional plan allowance coverage and an actual upcoming trainer-assigned session. Adult customer imports and other optional tools no longer block a new academy. The final review links to the customer portal, summarizes booking notice/preferences/credits, shows Stripe readiness and draft-only messaging, and requires acknowledgement.

Completion is stored once per server-selected academy. A brief dismissible celebration respects reduced motion, and the checklist disappears across reloads/devices. Later schedule or resource changes do not replay onboarding. Academy setup retains a deliberate Review setup guide action plus a collapsed list of optional additions. Reopening the guide cannot repeat the finish/celebration flow.

The overview now prioritizes the academy-local day, next sessions, booked spots and useful customer/rider/offering summaries. Session links open the actual session and relevant month. Restricted users see only permitted features; billing attention additionally requires customer access. Existing booking updates and recent activity remain. Outdated setup language about UTC-only calendars and upcoming recurrence was replaced with current behavior.

Architecture: separate readiness and day-summary rules, completion service and focused UI modules. No new package or external service. Migration 0022_short_sway adds academy_onboarding; no destructive change. Completion rereads tenant data, requires setup management and review acknowledgement, and inserts its row/audit atomically with retry protection. Stripe status uses matching current catalog snapshots, not any historical price. Core setup completion does not activate payment processing, message delivery or claim pilot-launch readiness.
