# Release 0.20 — Academy setup, community access and simpler offerings

Academy setup now has an Hours of operation section with a readable Monday–Sunday overview, academy time zone and separate date changes. Edit hours offers Weekly hours and Date changes. Every weekday can be open/closed with independent start, end and breaks; Monday can be copied to the remaining weekdays. Select individual dates or a cross-month range and apply custom opening hours/breaks or Closed all day to the selection. Repeat for different dates, then Save academy schedule once. Unfinished date selections block saving with a clear message. Existing date changes can be edited or returned to weekly hours.

Specific date hours replace that weekday's entire hours/breaks. Legacy closure dates remain supported; an explicit date override takes precedence. Removing a change restores the weekly baseline. Shared hours resolution drives availability displays, both monthly planners, session validation, admin enrollment and customer booking/rescheduling. Trainer personal hours still intersect academy hours, and current reservations still block time. Changes never delete or move existing lessons; affected sessions stop accepting new registrations. Staff must separately reconcile existing bookings. New trainer/intern defaults copy weekly academy hours without copying its date exceptions, which apply through the shared business boundary.

Lessons & Services now offers Delete with confirmation on each offering. Deletion is reversible archival: it disappears from active offerings and new scheduling selectors, and server session/month planning rejects it even from stale clients. Existing sessions, enrollment, payment/membership records and historical names remain unchanged; already-published sessions retain their booking behavior. Deleted offerings can be restored from a collapsed section. Program-management permission and tenant scope are enforced. Payment collection remains unconnected.

Trainer reviews are retired. Removed admin settings/moderation UI, family submission UI, directory ratings, trainer-choice reviews, review runtime modules/types/styles, and review-read queries. Legacy admin actions return HTTP 410, family submissions are rejected, and old settings cannot re-enable the feature. Old review rows and the historical migration/schema remain intact but are not read, returned or modified. Tests seed legacy enabled/approved data to verify it stays inaccessible. Prior release notes describe historical behavior only; onboarding and roadmap now reflect removal.

Academy setup also includes structured address (street, optional arrival details, city, region, postal code, country), business phone/email/website and optional GroupMe configuration. Customer Account displays directions, call/email/copy email and website actions. A discoverable community invitation appears on Home and Account only after family signup/adult confirmation and when enabled. The actual invite URL is withheld server-side from unsigned-up or non-adult family records and when disabled. The academy must paste its own HTTPS GroupMe sharing URL and enable it. No invitation is fabricated. GroupMe host/path validation rejects lookalikes, credentials, executable URLs and non-invitation paths. Public business contact details remain visible as academy metadata.

GroupMe is link-based only: no OAuth token, API client, message synchronization, automatic membership, notifications or tracking of whether a family joined. Parents make their own join decision in GroupMe; EO email/SMS opt-ins stay independent. The academy can remove or disable the card. Invitation links can be forwarded by recipients; academy setup explains that access is governed in GroupMe. Verified against Microsoft's GroupMe share-link instructions (https://support.microsoft.com/en-us/groupme/how-do-i-create-a-share-link-in-groupme) and official share_url shape (https://dev.groupme.com/docs/v3). An academy's actual link and cross-app join flow cannot be verified without that configuration. Three new contact tests cover URL safety, tenant-scoped updates without overwriting identity, adult-only invite disclosure, disabling and unchanged consent.

Architecture: date override resolution is shared in domain/availability.ts, with one reusable availability validation schema replacing the embedded server parser. One date-hours editor composes the existing single/range calendar instead of adding a calendar dependency. Offering archival reuses resource JSON and existing tenant/permission routes. No new packages, database migrations, environment variables or service permissions. Existing atomic booking/reservation and retry guards remain. Scope stays within one academy; both planner versions are retained.

Validation: npm run check:release passed TypeScript, all 145 tests and the production build. Nine new hours/deletion tests cover date isolation, replacement/restoration semantics, legacy closures, IANA/DST boundaries, exact free intervals, server validation/persistence, booking denial with existing-session preservation, tenant/permission boundaries, reversible offering removal and stale planner rejection. Two retirement tests replace five obsolete review feature tests. Existing auth/isolation, consent, payments-as-manual, scheduling/review-snapshot, concurrency and retry coverage passed. git diff --check passed.
