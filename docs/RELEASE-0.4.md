# 0.4 — Family portal foundation

Customer route `/portal?academy=<academy-id>` opens from the admin academy switcher. Mobile-first Home, Book, My riders and Account share the existing academy records. Family signup, rider profiles, favorites, trainer/horse directory, upcoming registrations, booking confirmation, cancellation and atomic rescheduling are persistent. Academy cancellation/rescheduling notice is editable in Academy Setup (0–720 hours; default 24). Customer times display in their browser time zone.

Family identity uses a new scoped account mapping with unique tenant/user and tenant/customer indexes. Signup creates a new CRM customer atomically; matching email alone never claims an existing record. Existing customer migration/linking is deliberately not automatic and needs a verified invitation/claim workflow before onboarding established families. Signup explains this pilot limitation. Staff can link riders to the new family customer in admin. No Site audience changes: additional testers still require access through the private Sites gate.

Server reads whitelist fields and expose only the family's customer, riders, memberships and registration identities; session seat counts and academy directory contain no other family identities. Photo reads verify academy/directory scope and family access for horse/trainer images. Family writes enforce ownership and cannot alter skill levels, billing, memberships or staff permissions. New riders start Beginner; instructors assign levels. Customer contact preferences save without sending messages.

Admin and family booking reuse the same enrollment validation and SQLite capacity/conflict triggers, including weekly availability, dates off and rider suitability. Rescheduling validates first, then replaces the enrollment in one D1 transaction, so a failed replacement retains the original. Audit entries record customer actions. Availability reads exclude unrelated historical sessions and group reservations by session in one pass. No new dependencies; one append-only mapping migration; UI/forms/types/services separated.

Pilot boundaries: free sessions and any academy membership-gated session with an active manual membership can be booked. There are no plan-specific entitlements or lesson-credit deductions yet. Paid offerings and private parties direct families to the academy; there is no live checkout, subscription billing, refund processing, waiver acceptance, homework or automated messaging. Cancellations release registrations without changing billing or memberships. Customer identity currently uses ChatGPT sign-in, not a standalone email/password login.

Validation: TypeScript, production build, 35 SQLite/domain tests covering tenant/family isolation, identity claims, protected fields, payment/membership gates, shared registrations, dates off, cancellation notice and atomic rollback. Managed browser preview still returns connection refused, so visual and authenticated end-to-end browser QA remain incomplete. Owner-private staging only; not ready for public/customer rollout until the remaining integrations and browser QA pass.
