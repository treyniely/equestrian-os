# Release 0.28 — Saved colors for individual offerings

The Month/Week/Day calendar now colors each offering by its own saved calendarColor rather than its broad template. Private 30 and Private 60 can have separate colors. The visible-date offering key identifies each color by its full offering name. The weekly planning preview, offering cards and customer booking labels use the same mapping.

New offerings automatically choose an unused palette color where available. Eleven readable palette colors are available; after all are used, automatic assignment balances reuse. The academy can choose a different palette color in Lessons & Services → Edit offering → Calendar color. Intentional duplicate colors are permitted. This is not a guarantee of unlimited visually unique hues.

Existing offerings receive deterministic defaults from the complete academy catalog. Saving any offering freezes prior unconfigured defaults in the same transaction before adding/updating that offering, preventing new offers from recoloring existing ones. Saved colors survive rename, duration changes, filtering, archiving and restoration. The color field is validated server-side and lives in the existing JSON details; no table migration or new dependency. Rider-level colors, booking access and billing are unchanged.
