# Release 0.17 — Lesson, days, time window

The lesson-planning screen now asks What are you teaching?, Which days?, and What time? From/Until replaces session-count arithmetic. A single available riding space is preselected and shown under More options; multiple spaces require an explicit Where choice. Weeks default to every occurrence in the month. Breaks between lessons, specific weeks, location and horses/supporting staff are grouped under More options. Mounted group offerings retain their existing horse-capacity requirements; private horses remain optional.

Open windows are suggested automatically after selecting a lesson, using its duration, trainer/academy availability, selected days and existing/proposed work. The separate Find available times button is removed. Choosing a suggested window preserves its duration. Availability reference is collapsed under View trainer hours & days off.

A live plain-language summary shows the lesson count per teaching day, weekdays, window and total fitting sessions for the selected month. Add to [month] stores a local proposal and collapses the editor into an editable summary card. Staff can Edit, Remove, add another schedule or Review month. The review action is shown only after completing/canceling the editor, preventing unsaved edits from being silently ignored. Only final Publish creates bookable sessions and any selected announcement draft.

The shared domain window generator fills complete lessons inside the chosen local window. It jumps to real break, opening-hour and existing-booking boundaries, respects staff/academy closures and selected resources, and leaves insufficient trailing minutes unused. User-configured between-lesson gaps remain supported. Existing count-based blocks remain compatible. Window occurrence keys use their actual timestamp so manual exclusions cannot shift to a different lesson if availability changes.

Server preview and publication use the same expansion rules. Publication compares a reviewed slot snapshot against fresh availability, including times, duration/capacity and occurrence keys. A changed result requires another review, rather than silently publishing fewer/different sessions. Existing atomic reservation guards, tenant permissions, idempotency fingerprints and 100-session/800-write bounds remain. All session counts are recomputed server-side; the client estimate is not trusted.

Architecture: isolated LessonScheduleEditor plus a pure lesson-window module; parent planner handles local proposals and final review. Old expanded-rule styles are removed. No dependencies, database migrations, settings, secrets or permissions added. Optional endTime extends the validated plan payload; it is not a new persisted recurring-series model. Rollback: restore 0.16.2. Published sessions retain the same existing schema.

Validation: TypeScript, all 123 automated tests and production build passed before publication. Four new tests cover exact lunch-boundary resumption, booking conflicts, gaps, day-off exclusion, full-lesson end bounds, daylight-saving consistency, server counts, stable occurrence identities and stale-review rejection without partial publication. Existing legacy planning, authorization, concurrency, family booking and draft tests remain passing.

Source UI audit covers the three main choices, automatic suggestions, More options, live summaries, Add/Edit/Cancel retention, one-vs-multiple location handling, review gating, header Back/close controls and mobile stacking. Managed browser preview continues to refuse connections, with no evidence of recovery after the last failed attempt. Browser screenshots, keyboard interactions, zoom and 390/768/1440px visual QA remain unverified; no visual pass is claimed. Email delivery and Stripe checkout remain unconnected as documented in prior releases.
