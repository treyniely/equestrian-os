# 0.9 — Automatic academy logo fitting

Academy logo upload recommends 1080 × 1080, accepts PNG/JPEG/WebP originals up to 8 MB, and prepares a square PNG in the browser. The complete logo is proportionally fitted inside an 84% safe area with transparent padding; no crop, generative redraw or fabricated detail. Small sources are flagged when enlarged. Preview, status animation, reduced-motion fallback and prepared PNG download precede an explicit academy Save. No external AI service is used and no source asset is sent elsewhere for preparation.

Only academy logos use this flow; horse/trainer photos retain center-cropped profile behavior. The saved prepared logo feeds existing palette detection. The upload is blocked while preparation runs, failed decoding cannot fall back to cropped-original upload, and stale processing results are discarded when another file is chosen. Prepared PNG uploads directly through the existing permission/tenant-scoped image API. Oversized prepared PNGs use a bounded 1080 WebP for storage; the download stays PNG. Extremely detailed files that remain over the server limit fail clearly. Decoded sources over 40 megapixels are rejected.

New UI and browser upload logic are isolated in academy-logo-upload; pure fit geometry is in domain/logo-fit. No dependencies, schema or audience changes. No promise of recovered detail from a low-resolution source; future AI enhancement would require a separate provider and review flow. Code-only rollback is supported; saved square assets remain valid.

Validation: check:release passed TypeScript, 65 domain/authorization/SQLite tests and production build. Source QA covers async replacement/unmount behavior, no-crop preview, download state, validation and reduced-motion styling.
