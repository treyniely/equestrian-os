# Release 0.22 — Optional riding spaces and two brand palettes

Calendar setup now starts with the offering, trainer and time. Riding space is optional in individual sessions, the trainer/academy month planner, Classic weekly planning, day fill and copy. It defaults to Decide at the barn even when exactly one space exists. Space selection lives in a collapsed optional disclosure. New setup no longer requires adding riding spaces. The Riding spaces feature remains available to academies that want reservations.

Without a selected space, no arena reservation is created. Trainer, academy hours, time off, suitability, supporting intern and existing reservation checks continue. Selecting a space validates its tenant-owned resource and its hours/conflicts as before. Copied slots preserve whether a space was selected. Editing an exact planned slot preserves its original trainer/space unless deliberately changed; the global selection for new slots cannot silently replace those assignments. Existing published reservations are unchanged. Both month planner views remain available.

Academy branding now shows exactly two curated options after reading a saved logo. Each option displays its button color, matching tint/accent, example button and text contrast. Multiple sampled colors remain an internal input rather than additional choices. A one-color logo gets a same-family alternative; monochrome/empty samples get neutral options. Failed image loading leaves custom hex entry available. Selection is explicit and indicated by text, a check and aria-pressed, not color alone.

Custom hex values remain editable. For shades too light for the portal's configured light surfaces, the editor shows the original and the proposed matching darker shade before saving. The adjustment is the closest passing shade along the original-to-black mixing path, not a claim of a globally nearest perceptual color. Normal button/hover text is checked at 4.5:1; button fills against white, #F8F8F4 and their derived tint meet our 3:1 policy. Navigation/accent text meets 4.5:1 against those backgrounds. Readable black/white button text is derived automatically. Preview, server save and portal rendering use the same deterministic, idempotent rules. Older saved light colors are safely interpreted on portal read without rewriting their records. Buttons, navigation, community panels and plan balances carry the palette. Logo artwork is unchanged.

Contrast references: WCAG 2.2 SC 1.4.3 (https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) and SC 1.4.11 (https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast). These are specific color-contrast checks, not certification of whole-site WCAG conformance or ADA compliance. In particular, a dark border or label can satisfy some non-text contrast cases; the fill policy is a deliberate stronger consistency constraint for these portal themes. Full accessibility review remains necessary.

Architecture: optional arenas reuse the same PlanBlock payload with an empty/omitted arena normalized by the server, and reservation pairs are created only for selected resources. No database migration, provider configuration, permission change or dependency added. The shared color engine adds one bounded matching function; palette curation uses the existing pixel sampler and removes the old multi-button sample grid/styles. Existing atomic booking allowance and conflict guards remain unchanged.

Validation: npm run check:release passed TypeScript, all 165 tests and production build; git diff --check passed. Six new tests cover exactly two distinct palettes across multicolor/single-color/monochrome cases, deterministic/idempotent matching across 216 RGB samples, light-surface/text contrast, individual scheduling without space, trainer conflict enforcement, explicit space conflict/foreign ID rejection, fill/copy without space profiles and Classic month publication without space. Existing branding tests now assert the effective accessible shade rather than raw light-color retention. All prior plan/payment-isolation, concurrency, permissions, consent and booking checks passed.

Source UI review covers collapsed optional fields, primary flow without a space requirement, saved assignments, two palette selection states, original/matched color labeling, loading/failure/invalid/disabled states, long labels, matching field insets, responsive cards and focus outlines. Browser screenshots, keyboard/200% zoom and 390/768/1440px checks remain unverified: the managed preview most recently returned net::ERR_CONNECTION_REFUSED and no recovery evidence exists. No visual QA pass is claimed. No marketing changes.
